### Tugas 5
1. Debouncing adalah teknik untuk menunda eksekusi suatu fungsi hingga tidak ada lagi input baru dari pengguna dalam jeda waktu tertentu. Teknik ini sangat penting pada fitur pencarian berbasis AJAX karena tanpa debouncing, setiap kali pengguna menekan tombol saat mengetik, aplikasi akan terus mengirimkan permintaan baru ke server. Dengan adanya debouncing, permintaan AJAX hanya dikirim setelah pengguna selesai atau berhenti mengetik, sehingga efisiensi bandwidth meningkat, beban kerja server berkurang, dan penumpukan respons yang berlebihan dapat dicegah.
2. Penggunaan await saat memanggil fungsi fetch() bertujuan untuk menghentikan sementara eksekusi kode di dalam fungsi async sampai Promise yang dikembalikan oleh fetch() selesai diproses dan menghasilkan objek respons. Jika await tidak digunakan, program akan langsung mengeksekusi baris kode berikutnya sebelum data dari server selesai diambil. Hal ini menyebabkan variabel penyimpanan hanya memuat status Promise yang masih pending, bukannya data asli, sehingga pemrosesan lanjutan seperti pembacaan JSON akan memicu kegagalan atau error.
3. Serangan Cross-Site Scripting (XSS) merupakan bentuk peretasan web di mana penyerang berhasil menyuntikkan kode skrip berbahaya ke dalam situs agar dieksekusi oleh peramban milik pengguna lain. Data yang ditampilkan melalui AJAX dan JavaScript lebih rentan terhadap serangan ini dibanding template Django karena sistem template Django secara bawaan menerapkan pembersihan otomatis (auto-escaping) pada karakter khusus HTML. Sebaliknya, manipulasi tampilan menggunakan JavaScript seperti perintah innerHTML tidak melakukan pembersihan kode secara otomatis, sehingga skrip jahat yang dikirim dari AJAX akan langsung dianggap sebagai kode aktif dan dieksekusi oleh peramban.

**Jawaban Reflektif**
1. REST (Representational State Transfer) merupakan gaya arsitektur API yang mengatur komunikasi antara client dan server menggunakan HTTP method seperti GET, POST, PUT, PATCH, dan DELETE. API yang mengembalikan JSON saja belum tentu RESTful karena REST juga memiliki prinsip seperti penggunaan resource, HTTP method sesuai fungsinya, status code, dan komunikasi stateless. PUT digunakan untuk memperbarui seluruh data pada suatu resource, sedangkan PATCH digunakan untuk memperbarui sebagian data saja. Contohnya, pada endpoint detail achievement, PUT digunakan saat mengirim data lengkap achievement yang dapat diubah, sedangkan PATCH digunakan saat hanya mengirim field yang ingin diperbarui.
2. Serializer pada Django REST Framework berfungsi untuk mengubah data dari model atau objek Python menjadi format JSON dan sebaliknya, sekaligus melakukan validasi terhadap data yang diterima dari client. Dibandingkan merakit dictionary secara manual menggunakan JsonResponse seperti pada Tutorial 05, serializer lebih praktis karena dapat mengurangi penulisan kode berulang, mempermudah validasi data, serta terintegrasi langsung dengan model Django melalui ModelSerializer. Dengan demikian, pengelolaan data API menjadi lebih terstruktur dan mudah dipelihara.
3. Autentikasi (authentication) merupakan proses untuk memastikan identitas pengguna yang mengakses API, sedangkan otorisasi (authorization) merupakan proses untuk menentukan hak akses pengguna terhadap suatu tindakan. Contohnya  pengguna yang berhasil login belum tentu memiliki izin untuk menghapus data. Oleh karena itu, Django REST Framework menggunakan permission class untuk memeriksa hak akses di sisi server. Pemeriksaan ini penting karena menyembunyikan tombol pada template saja tidak cukup aman, sebab pengguna masih dapat mengirimkan request secara langsung melalui Postman atau browser.
4. Pada SessionAuthentication, CSRF token tetap diperlukan untuk request yang mengubah data seperti POST, PUT, PATCH, dan DELETE karena browser secara otomatis mengirimkan cookie session ketika berkomunikasi dengan server. CSRF token berfungsi memastikan bahwa request tersebut bukan berasal dari serangan Cross-Site Request Forgery. Sementara itu, force_authenticate tidak cukup untuk membuktikan perlindungan CSRF berjalan karena fitur tersebut melewati proses autentikasi normal. Oleh karena itu, pengujian CSRF perlu dilakukan menggunakan APIClient(enforce_csrf_checks=True) agar mekanisme perlindungan CSRF benar-benar diuji.
